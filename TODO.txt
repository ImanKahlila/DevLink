================================================================================
BACKEND
================================================================================

1. Database & Prisma Schema Modeling
   [ ] User & Profile Model:
       - Store id, email, name, avatarUrl, headline, bio, location, createdAt, updatedAt.
       - Add skills (string array or dedicated Skill relation) to enable skill-based searching.
   [ ] Post / Note Model:
       - Store id, authorId, content, tags, timestamps, and relations to likes, saves, and replies.
   [ ] Interaction Models:
       - Like / Appreciation model (unique compound index on [userId, postId]).
       - SavedPost / Bookmark model (unique compound index on [userId, postId]).
       - Reply / Comment model (id, postId, userId, content, createdAt).

2. Authentication & OAuth Implementation (using Clerk is fine for this)
   [ ] User Registration & Onboarding Endpoint:
       - Implement /api/auth/register (or Clerk webhook / user sync) to store newly registered user profile info: name, email, skills, headline, bio, location.
   [ ] OAuth / Auth Provider Integration:
       - Set up Clerk or OAuth flow (e.g. GitHub/Google once configured) or secure email login.
       - Implement /api/auth/login, /api/auth/callback, /api/auth/me, and /api/auth/logout.
   [ ] Session & Token Verification:
       - Implement Clerk middleware or JWT / session middleware to protect authenticated API endpoints.

3. Posts & Feed API
   [ ] Feed Endpoint (GET /api/posts): Return chronological feed posts with author profiles, like count, reply count, and booleans for isLiked and isSaved by current user.
   [ ] Create Note Endpoint (POST /api/posts): Validate input, create post, and associate with authenticated user.
   [ ] Like Endpoint (POST /api/posts/:id/like or DELETE): Toggle user appreciation on a post and return updated count.
   [ ] Save Endpoint (POST /api/posts/:id/save or DELETE): Add/remove post from user's bookmarks.
   [ ] Replies Endpoints:
       - GET /api/posts/:id/replies: Fetch threaded replies for a specific post.
       - POST /api/posts/:id/replies: Submit a reply to a post.

4. Search API
   [ ] Search Endpoint (GET /api/users/search?q=...):
       - Implement case-insensitive search matching against name, headline, and skills.
       - Return formatted user cards with role, avatar, and skill badges.

5. Profile & Settings API
   [ ] Profile Endpoints:
       - GET /api/users/:id or /api/users/profile (fetch current profile).
       - PUT /api/users/profile (update display name, headline, bio, photo).
   [ ] Settings Endpoint:
       - Store notification & presence preferences (excluding removed circle digest / appearance settings).
